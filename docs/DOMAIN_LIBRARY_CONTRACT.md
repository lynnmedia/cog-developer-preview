# Cog Domain Library Contract Specification

This document defines the standard contract and conformance rules that every cognitive domain library in `cog` must satisfy.

---

## 1. Required Schema & Fields

Every domain library object must implement the `DomainLibrary` interface, which defines the following properties:

| Property | Type | Description |
|---|---|---|
| `id` | `string` | Unique namespace identifier starting with `cog:domain:` (e.g. `cog:domain:research`). |
| `name` | `string` | Human-readable name. |
| `description` | `string` | Detailed description of the reasoning purpose. |
| `capabilities` | `readonly DomainLibraryCapability[]` | Supported cognitive capabilities. |
| `supportedPatterns` | `readonly string[]` | Available reusable template patterns. |
| `generate` | `(params: Record<string, any>) => string` | Generator function returning valid `.cog` program source. |

---

## 2. Supported Primitives & Patterns

Domain libraries must map their parameters to the core `.cog` primitives:
- **Entities**: Defining conceptual elements (`define entity`) representing observations, extractions, findings, decisions.
- **Relations**: Defining associations (`relate`) such as `differs-from`, `clustered-into`, `blocks`, `recommends`.
- **Resolutions**: Processing levels and declaring transitions (`resolve`).
- **Views**: Exposing targeted perspectives (`view`).
- **Emissions**: Specifying terminal output payloads (`emit`).

---

## 3. Workflow Conformance

Workflows generated by a domain library must support:
- **Single-Pass Evaluation**: No dynamic backpropagation; planning and execution flows forward from bind to emit.
- **Topological Sorting**: Dependencies between entities must form a DAG.

---

## 4. Adapter Awareness

Domain libraries must remain kernel-neutral but can request adapter-specific actions or kind mappings. They must not assume or hardcode AWB or external runtime details directly into their core logic.

- **No Adapter**: System uses standard fallback/neutral kind mappings.
- **Active Adapter**: Adapters like `momAdapter` or `decisionAdapter` map kinds and inject custom execution plan steps.

---

## 5. Validation Rules

A domain library is considered conformant only if its generated `.cog` programs:
1. Lexically and syntactically parse without errors.
2. Formulate correct semantic IR via the compiler (`compileCog`).
3. Pass all core validation checks (`validateCog`).
4. Execute deterministically to completion on the core runtime (`executeCog`).
