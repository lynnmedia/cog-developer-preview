# Cog Compatibility Contract

This document outlines the stability guarantees and compatibility contracts for downstream consumers of the `cog` kernel.

## 1. Stable Surfaces (Guaranteed Stability)

Downstream projects and platforms can reliably depend on the following surfaces:

### 1.1 Language Parser & Grammar Syntax
- All core keywords (`define`, `entity`, `kind`, `level`, `value`, `relate`, `resolve`, `emit`, `constrain`) will remain backward-compatible within the same major version.
- Valid programs written in `.cog` v0.3 are guaranteed to parse and compile successfully across future minor/patch version releases.

### 1.2 Intermediate Representation Schema (`CoreIR`)
- The output structure of the compiler (entities array, relations array, views, emissions, resolutions, and execution graph nodes) is stable.
- Attributes fields inside entities will consistently preserve raw payload maps.

### 1.3 Core Execution API
- Calling `executeCog(ir, context, adapter)` remains the standard invocation hook.
- The shape of `CoreExecutionResult` (with success boolean, plan, emissions list, and trace) is fully stable.

---

## 2. Evolving & Unstable Surfaces (Subject to Change)

The following areas are subject to ongoing improvements, and breaking changes may occur without a major version increment:

### 2.1 Domain Libraries and Examples
- Experimental domain libraries (such as `devotionalIntelligenceLibrary` or `cognitiveEcologyLibrary`) are proofs-of-concept and might be updated or renamed.
- Integration foundations (e.g., helpers in `packages/cog-core/src/integration/`) are tailored to ecosystem proofs and are not guaranteed to remain static.

### 2.2 Trace Visualization Formats
- The visual layout, styling, and structural node types generated by `TraceVisualizationService` (including Mermaid flowchart shapes) are unstable and may change to support better human debugging experiences.

### 2.3 Incremental Compiler API
- Internals of `compileCogIncremental` and state management cache keys are internal optimizations and subject to refactoring.

---

## 3. Explicit Non-Guarantees

Downstream systems must **NOT** rely on:
- **Performance Thresholds**: Execution speed (duration_ms) is system-dependent.
- **Internal Helper APIs**: Any file or class path not explicitly exported from `packages/cog-core/src/index.ts`.
- **Log formats**: Output printed to `stdout` or `stderr` is for diagnostics only and is not structured for program parsing.
